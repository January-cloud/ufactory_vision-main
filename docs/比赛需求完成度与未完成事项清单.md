# 多工艺柔性产线比赛 — 需求完成度与未完成事项清单

> 依据文档：`多工艺柔性产线中机械臂自主决策与协同效能优化比赛方案.doc.pdf`
> （题号 DG-202607，发榜单位：山东泰莱电气股份有限公司）
>
> 本文档用于跟踪比赛"答题要求"与"评选标准"的完成进度，供团队规划后续开发。

---

## 一、PDF 硬性要求（第五节 答题要求）摘要

参赛作品需包含：

1. **技术方案报告**：系统阐述自主决策与协同优化模型的架构、核心算法
   （如多智能体强化学习、分布式优化、实时调度策略等）及创新点；
2. **可运行的软件仿真系统**（推荐 ROS / CoppeliaSim 等平台）：
   - 模拟一个包含 **至少 3 台机械臂** 和 **3 种以上不同工艺**（如取放、装配、检测）的柔性产线场景；
   - 演示在 **动态订单输入** 下系统的 **自主决策与协同效能**；
3. **鼓励**提供算法在真实机械臂平台上的验证视频或数据对比报告。

### 评选标准（第六节）

| 维度 | 权重 | 关键点 |
|------|------|--------|
| 创新性 | 30% | 自主决策模型、协同优化算法是否有理论/技术创新 |
| 技术可行性与有效性 | 30% | 提升节拍、降低空闲率、增强应对变化能力；KPI：任务完成时间、设备利用率、换型时间缩短比例 |
| 应用潜力与价值 | 25% | 切中柔性制造痛点、可推广、经济性 |
| 完成度与规范性 | 15% | 报告逻辑清晰、代码规范可读、演示材料完整 |

## 三、未完成部分（TODO 清单）

### 3.1 多工艺扩展：装配、检测（P0，硬性要求缺失项）
- **现状**：全项目只有一种工艺——取放。`task_builder.py` 的 `build_pick_and_place()` 生成 10 步 `move`/`vacuum` 序列，无装配、无检测。
- **需要实现**：
  - 新增动作类型：装配（夹取 → 对准 → 插入/放置 + 紧固）、检测（移动到检测位 → 拍照 → 判定 pass/fail，可在判定失败时重试或呼叫人工）。
  - `TaskBuilder` 增加 `build_assembly()` / `build_inspect()` 等构建方法；
  - 配置中定义每臂/每订单的"工序链"（如 取放 → 装配 → 检测）；
  - 仿真服务器动作协议若只支持 move/vacuum，需同步扩展协议或先用 move 模拟装配位姿。
- **涉及文件**：`simulation/task_builder.py`、`simulation/sim_3arm/sim_arm_controller.py`、`simulation/config_sim_3arms.json`、`simulation/simulation_client.py`。

### 3.2 动态订单输入（P0，硬性要求缺失项）
- **现状**：`simulation/external_input.py` 仅支持 HTTP `POST /grasp_target` 接收单个抓取目标坐标，不是"订单/工序切换"级别的动态任务输入。
- **需要实现**：
  - 定义订单数据结构：工件类型、数量、所需工序序列、优先级、到达时间；
  - 新增订单接收接口（如 `POST /order`）与订单队列；
  - 订单 → 生成任务分配，驱动各臂执行对应工序；演示"订单变化 → 换型"。
- **涉及文件**：`simulation/external_input.py`（或新增 `order_manager.py`）、`simulation/sim_3arm/sim_coordinator.py`。

### 3.3 KPI 量化统计（P0，直接对应 30% 可行性评分）
- **现状**：仅统计每臂抓取次数（`MultiArmCoordinator.get_grasp_counts()`）。无任务完成时间、设备利用率、换型时间、OEE 等指标。
- **需要实现**：
  - 在 `task_recorder.py` 落盘数据基础上做离线统计：各臂/各类型产量、任务耗时、空闲率、换型时间；
  - 运行期实时统计模块（可选）：输出节拍（takt）、利用率、吞吐率；
  - 生成数据对比报告（如"加协调 vs 不加协调"、"单臂 vs 三臂"的指标对比表）。
- **涉及文件**：新增 `simulation/sim_3arm/stats.py`（或 `metrics.py`），复用 `task_recorder.py`。

### 3.4 真实视觉物体识别（P1，补强自主决策）
- **现状**：`object_mapping.py` 的 `ObjectMapper.recognize()` 用**坐标最近邻匹配模拟**识别，代码注释明确其为占位实现。
- **需要实现**：
  - 用视觉分类器（YOLO / 分类 CNN）对相机彩色图分类出物体类型，再走 `recognize_by_type()` 查表；
  - 接口已预留：只需替换 `recognize()` 内部实现，`sim_arm_controller.py` 无需改动。
- **涉及文件**：`simulation/sim_3arm/object_mapping.py`、新增视觉分类模型代码。

### 3.5 协同调度与决策算法（P1，对应 30% 创新性评分）
- **现状**：协同为规则式启发（区域锁 + 全局冷却 + 发送串行化），**无**多智能体强化学习 / 分布式优化 / 实时调度算法。
- **需要实现**：
  - 任务优先级调度：高优先级订单/工序抢占；负载均衡的任务分配（按各臂实时占用/位置）；
  - 可选进阶：多智能体强化学习（MARL）训练协同策略，替换/叠加规则式协调；
  - 在技术方案报告中论证创新点。
- **涉及文件**：`simulation/sim_3arm/sim_coordinator.py`、`multi_arm/coordinator.py`，或新增调度模块。

### 3.6 技术方案报告（P1，交付物 1）
- **现状**：仓库无方案报告文档（现有 `docs/三臂协同抓取系统设计方案.md` 覆盖系统设计，但缺算法论证与创新点）。
- **需要编写**：架构总览、核心算法（调度/识别/协同）说明、创新点、与竞品对比、KPI 预期。

### 3.7 真实机械臂验证（P2，鼓励项）
- **现状**：真机代码齐备但未在真机跑通、无验证视频或数据对比报告。
- **需要**：在 xArm + RealSense 平台上复现三臂抓取，录制视频并产出数据对比报告（仿真 vs 真机）。

## 四、建议优先级与排期

| 优先级 | 事项 | 目标（对应评分） |
|--------|------|------------------|
| **P0** | 3.1 多工艺（装配/检测） | 满足硬性要求"3 种以上工艺" |
| **P0** | 3.2 动态订单输入 | 满足硬性要求"动态订单输入下自主决策与协同" |
| **P0** | 3.3 KPI 量化统计 | 30% 可行性有效性（节拍/利用率/换型时间） |
| **P1** | 3.5 调度/决策算法 | 30% 创新性 |
| **P1** | 3.4 真实视觉识别 | 补强自主决策完整性 |
| **P1** | 3.6 技术方案报告 | 交付物 1 + 15% 规范性 |
| **P2** | 3.7 真机验证 | 鼓励项加分 |

> 建议按 **P0 → P1 → P2** 顺序推进；P0 三项是硬性要求与高分项，优先保证。
> 3.3 已由 `task_recorder.py` 落盘铺好数据基础，实现成本最低。
