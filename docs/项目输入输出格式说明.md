# ufactory_vision 项目输入值和输出值说明

> 基于 GGCNN + RealSense + xArm 的视觉引导机器人抓取系统

---

## 一、核心数据流

```
深度图 (480×640 float32)
    │
    ▼  裁剪+修复+缩放
深度图 (300×300, [-1,1])
    │
    ▼  GGCNN2 推理
4通道热力图 (300×300)
    │
    ▼  峰值提取 + 相机投影
相机系抓取点 [x, y, z, ang, width, depth_center]
    │
    ▼  坐标变换 (手眼标定 + 实时位姿)
基坐标系目标 [X, Y, Z, Roll=180, Pitch=0, Yaw°]
    │
    ▼  xArmAPI.set_position()
机械臂执行
```

## 二、系统整体输入

### 2.1 传感器输入

| 输入项 | 类型 | 维度/格式 | 来源 | 说明 |
|--------|------|-----------|------|------|
| 深度图 | `numpy.ndarray` (float32) | `(H, W)`，典型 `(480, 640)` | RealSense D435/D555 或 OAK-D PoE | 单位: 米，含 NaN 无效区域 |
| 彩色图 | `numpy.ndarray` (uint8) | `(H, W, 3)` BGR | 同上相机 | 用于可视化显示，不参与推理 |
| 相机内参矩阵 K | `numpy.ndarray` (float) | `(3, 3)` | 相机 SDK `get_intrinsics()` | `[[fx, 0, cx], [0, fy, cy], [0, 0, 1]]` |
| 机械臂实时位姿 | Python `list` | `[x, y, z, roll, pitch, yaw]` (米/弧度) | xArm API `get_position(is_radian=True)` | 每帧获取，用于坐标系转换 |
| 末端数字输入 TI0 | `int` | `0` 或 `1` | xArm API `get_tgpio_digital(0)` | 真空吸盘负压检测 (1=吸住) |
| 机械臂错误码 | `int` | 整数错误码 | xArm API `arm.error_code` | 0=正常，非0=故障 |

## 三、GGCNN2 神经网络

### 3.1 模型结构

- **模型类**: `GGCNN2` (`ggcnn/models/ggcnn2.py`)
- **架构**: 4层卷积 → 2层空洞卷积(dilation=2,4) → 双线性上采样 → 4个独立输出头
- **参数量**: 约 6.2 万
- **预训练权重**: `models/epoch_50_cornell` (295 KB), Cornell 数据集训练 50 轮

### 3.2 模型输入

| 项目 | 规格 |
|------|------|
| 类型 | `torch.Tensor` (float32) |
| 形状 | `(1, 1, 300, 300)` 即 `(batch=1, channel=1, H=300, W=300)` |
| 值域 | `[-1, 1]`，零均值归一化后的深度图 |
| 预处理 | 原深度图(480×640) → 裁剪底部 300×300 → NaN inpainting → resize → clip |

### 3.3 模型输出 (4 通道)

```python
pos_output, cos_output, sin_output, width_output = model(depthT)
```

| 输出头 | 形状 | 含义 | 值域 |
|--------|------|------|------|
| `pos_output` | `(1, 1, 300, 300)` | 抓取质量图 — 每个像素作为抓取点的评分 | `[0, 1]`，越接近 1 越适合抓取 |
| `cos_output` | `(1, 1, 300, 300)` | 编码抓取角度的 cos(2θ) | `[-1, 1]` |
| `sin_output` | `(1, 1, 300, 300)` | 编码抓取角度的 sin(2θ) | `[-1, 1]` |
| `width_output` | `(1, 1, 300, 300)` | 推荐夹爪张开宽度 | `[0, 1]`，映射到 0~150mm |

角度解码: `ang = arctan2(sin_out, cos_out) / 2.0`

## 四、系统整体输出

项目的最终返回值是基坐标系下的 6 自由度抓取位姿 [X, Y, Z, Roll, Pitch, Yaw]（mm/度），
以及用于可视化的质量热力图。多臂模式下还会额外输出各臂运行状态和区域锁状态。

### 4.1 GGCNN 推理引擎输出

函数: `TorchGGCNN.get_grasp_img()` → 返回 `(grasp_img, result)`

```python
grasp_img, result = ggcnn.get_grasp_img(depth_image, K, robot_z)
```

#### `result` — 相机坐标系抓取点

| 索引 | 名称 | 类型 | 单位 | 说明 |
|------|------|------|------|------|
| `result[0]` | `x` | `float` | 米 | 抓取点 X (相机坐标系, 右) |
| `result[1]` | `y` | `float` | 米 | 抓取点 Y (相机坐标系, 下) |
| `result[2]` | `z` | `float` | 米 | 抓取点深度 (相机坐标系, 前) |
| `result[3]` | `ang` | `float` | 弧度 | 夹爪旋转角度 |
| `result[4]` | `width` | `float` | mm | 推荐夹爪宽度 (0~150) |
| `result[5]` | `depth_center` | `float` | mm | 中心区域平均深度 (碰撞避免用) |

失败时 `result = None`。

#### `grasp_img` — 可视化热力图

| 属性 | 值 |
|------|-----|
| 类型 | `numpy.ndarray` (uint8) |
| 形状 | `(300, 300, 3)` |
| 内容 | JET 色映射的质量热力图 + 绿色圆点标记抓取位置 |

### 4.2 坐标变换后的抓取目标 (机械臂可直接执行)

函数: `cam_result_to_base()` → 返回 6 元素 list

```python
[gp_base_x, gp_base_y, gp_base_z, roll=180, pitch=0, yaw_deg]
```

| 索引 | 名称 | 类型 | 单位 | 坐标系 | 说明 |
|------|------|------|------|--------|------|
| `[0]` | X | `float` | mm | 机械臂基坐标系 | 抓取目标 X |
| `[1]` | Y | `float` | mm | 机械臂基坐标系 | 抓取目标 Y |
| `[2]` | Z | `float` | mm | 机械臂基坐标系 | 抓取目标 Z (已加吸盘补偿) |
| `[3]` | Roll | `float` | 度 | — | 固定 180° (相机朝下) |
| `[4]` | Pitch | `float` | 度 | — | 固定 0° |
| `[5]` | Yaw | `float` | 度 | 基坐标系 | 归一化在 -π/2 到 π/2 |

直接传入 `arm.set_position(x=..., y=..., z=..., roll=..., pitch=..., yaw=...)` 执行。

### 4.3 多臂协同系统额外输出

| 输出项 | 类型 | 说明 |
|--------|------|------|
| `ArmState` | 枚举 | IDLE / LOCKED / MOVING / GRASPING / PLACING / RECOVERING / STOPPED / DISCONNECTED |
| `ZoneState` | 枚举 | FREE / OWNED / HAZARD (区域锁状态) |
| 臂间距离 | `float` (mm) | 实时计算，10Hz 监控，低于 `safety_radius_mm` 触发警告 |
| 区域锁租约 | `ZoneLease` | 含 arm_id, zone_name, remaining_s, 30s 自动过期 |
| 统计信息 | — | 各臂抓取计数、成功/失败次数 |

### 4.4 可视化输出

| 输出 | 模式 | 内容 |
|------|------|------|
| OpenCV 窗口 "RealSense-D435 AUTO" | 单臂 | 左: 彩色图 + 状态文字; 右: GGCNN 热力图 |
| OpenCV 窗口 "3-Arm Collaborative Grasping" | 三臂 | 三路相机拼合 + 全局状态面板 (臂状态/计数/区域/距离) |

按键交互:
- `q` / `ESC` → 退出程序
- `r` → 清除 HAZARD 区域 (三臂模式)
- `s` → 打印摘要 (三臂模式)

## 六、臂运行状态 (ArmState) 详细格式

> 定义位置: `multi_arm/config.py:21-29`  
> 使用位置: `multi_arm/coordinator.py` + `multi_arm/arm_controller.py`

### 6.1 枚举定义

```python
from enum import Enum

class ArmState(Enum):
    IDLE         = "IDLE"          # 在观察位，搜索目标中
    LOCKED       = "LOCKED"        # 已稳定锁定抓取目标
    MOVING       = "MOVING"        # 平移运动中
    GRASPING     = "GRASPING"      # 阶段2/3：精定位 + 下降抓取
    PLACING      = "PLACING"       # 搬运到释放点
    RECOVERING   = "RECOVERING"    # 错误恢复中
    STOPPED      = "STOPPED"       # 严重故障，需人工介入
    DISCONNECTED = "DISCONNECTED"  # 网络断开
```

### 6.2 运行时的序列化格式

在 `MultiArmCoordinator` 内部以枚举值存储，对外通过 `get_summary()` 以 `.value` 字符串输出：

```python
# coordinator.py 内部存储 (Dict[int, ArmState])
self._arm_states: Dict[int, ArmState] = {}

# get_summary() 对外输出 (Dict[int, str])
{
    "arm_states": {
        0: "IDLE",
        1: "LOCKED",
        2: "GRASPING",
    }
}
```

### 6.3 状态迁移规则

```
IDLE ──(目标锁定)──▶ LOCKED ──(触发抓取)──▶ MOVING ──(到位)──▶ GRASPING
  ▲                                                    │
  │                                                    ▼
  ├──────────────────(抓取完成)─────────────── PLACING ──(放下)──▶ IDLE
  │
  ├──── 任意状态 ──(检测到错误)──▶ RECOVERING ──(恢复成功)──▶ IDLE
  │                                     │
  │                                     └──(恢复失败)──▶ STOPPED (需人工介入)
  │
  └──── 任意状态 ──(网络断开)──▶ DISCONNECTED
```

进入 `RECOVERING / STOPPED / DISCONNECTED` 时，Coordinator 自动释放该臂持有的所有协调区锁。

### 6.4 可视化渲染

定义在 `multi_arm/visualizer.py:35-48`，每个状态对应显示颜色:

| 状态 | BGR 颜色值 | OpenCV 常量 | 视觉效果 |
|------|-----------|-------------|----------|
| `IDLE` | `(200, 200, 200)` | 浅灰 | — |
| `LOCKED` | `(0, 255, 255)` | 黄色 | 目标已锁定 |
| `MOVING` | `(255, 165, 0)` | 橙色 | 运动中 |
| `GRASPING` | `(0, 255, 0)` | 绿色 | 正在抓取 |
| `PLACING` | `(255, 0, 255)` | 品红 | 搬运放置 |
| `RECOVERING` | `(0, 165, 255)` | 橙红 | 错误恢复 |
| `STOPPED` | `(0, 0, 255)` | 红色 | 严重故障 |
| `DISCONNECTED` | `(0, 0, 128)` | 深红 | 网络断开 |

## 七、区域锁状态 (ZoneState) 详细格式

> 定义位置: `multi_arm/config.py:33-35`  
> 使用位置: `multi_arm/coordinator.py`

### 7.1 枚举定义

```python
class ZoneState(Enum):
    FREE   = "FREE"     # 空闲，任何臂可申请
    OWNED  = "OWNED"    # 已被某臂持有，附带租约 (ZoneLease)
    HAZARD = "HAZARD"   # 危险区，L2/L3 故障残留，需人工按 'r' 清除后才能使用
```

### 7.2 区域命名规则

| 区域类型 | 命名模式 | 示例 | 说明 |
|----------|----------|------|------|
| 独占区 | `exclusive_{arm_id}` | `exclusive_0` | 臂0独有，注册时自动获得，永不过期 |
| 协调区 | `coord_{arm_id}_{index}` | `coord_0_0` | 臂0可访问的第0号相邻重叠区，互斥锁，带租约 |

### 7.3 区域锁租约 (ZoneLease)

定义在 `multi_arm/coordinator.py:32-57`：

```python
class ZoneLease:
    arm_id: int           # 持有者臂编号
    zone_name: str        # 区域名称 (如 "coord_0_0")
    granted_at: float     # 授予时刻 (time.monotonic())
    lease_duration: float # 租约时长 (默认 30s, 独占区为 inf)
    renewed_at: float     # 最后续约时刻

    def renew(self)           # 续约，延长 lease_duration 秒
    def is_expired(self) -> bool  # 是否已过期
    def remaining_s(self) -> float # 剩余有效秒数
```

续约机制：持有协调区的臂每 5 秒 (`lease_renew_interval_s`) 主动续约一次。若臂线程崩溃或死锁，租约 30 秒后自动过期，区域回收为 FREE，防止死锁。

### 7.4 运行时的序列化格式

```python
# coordinator.py 内部存储
self._zone_states:  Dict[str, ZoneState] = {}  # 区域名 → 状态枚举
self._zone_leases:  Dict[str, ZoneLease] = {}  # 区域名 → 租约对象

# get_summary() 对外输出
{
    "zones": {
        "exclusive_0": {"state": "OWNED", "holder": 0},
        "exclusive_1": {"state": "OWNED", "holder": 1},
        "exclusive_2": {"state": "OWNED", "holder": 2},
        "coord_0_0":   {"state": "FREE",   "holder": None},
        "coord_1_0":   {"state": "HAZARD", "holder": None},
        "coord_1_1":   {"state": "OWNED",  "holder": 1},
        "coord_2_0":   {"state": "FREE",   "holder": None},
    },
    "any_hazard": True,   # bool: 是否有 HAZARD 区域
}
```

- `"state"` 是 `ZoneState.value` 的字符串
- `"holder"` 是 `int` 或 `None`，表示当前持有者的 arm_id
- `"any_hazard"` 是顶层快捷布尔字段

### 7.5 区域锁申请流程

```
Arm.arm_id ──► request_zone(arm_id, "coord_0_0", timeout_s=5.0)
                  │
                  ├─ 已持有该区? ──→ 直接返回 True
                  │
                  ├─ 区域 FREE? ──→ 获得所有权 + 创建 ZoneLease → 返回 True
                  │
                  ├─ 区域 HAZARD? ──→ 永久不可用 → 返回 False
                  │
                  ├─ 他人持有中 ──→ 加入等待队列
                  │      │
                  │      ├─ 前持有者释放 → 获得所有权 → 返回 True
                  │      ├─ 超时 (默认 5s) → 移除等待 → 返回 False
                  │      └─ 检测到死锁 → arm_id 较小方主动放弃 → 返回 False
                  │
                  └─ release_zone(arm_id, "coord_0_0")
```

## 八、get_summary() 完整结构

> 来源: `coordinator.py:560-582`

```python
def get_summary(self) -> dict:
    return {
        # arm_id → 状态字符串
```

## 九、仿真模式接口（新增）

> 代码位置: `ggcnn_grasping_demo/simulation/`
> 将物理机械臂控制替换为 HTTP 仿真调用, 支持从仿真服务器获取摄像头图像

### 9.1 仿真模式概述

仿真模式通过 HTTP 与仿真平台 `http://192.168.1.121:8080` 通信, 无需连接真实机械臂。
核心变化:

| 真实模式 | 仿真模式 |
|----------|----------|
| `arm.set_position()` | POST `/task` (JSON 任务序列) |
| `arm.set_vacuum_gripper()` | POST `/task` (vacuum 动作) |
| `arm.get_position()` | 硬编码观察位虚拟位姿 |
| `arm.get_tgpio_digital(0)` | 序列内 wait 字段模拟 |
| RealSense D435 SDK | 可选: POST `/get_camera` 从仿真服务器获取图像 |

### 9.2 输入 (仿真平台 → 本系统)

#### 9.2.1 摄像头图像 (`/get_camera`)

**请求:**
```
POST http://192.168.1.121:8080/get_camera
Content-Type: application/json
Body: {}
```

**响应 (成功):**
```json
{
    "success": true,
    "rgb_image": "<base64 编码的 JPEG/PNG 图像>",
    "depth_image": "<base64 编码的 16-bit PNG 深度图 (mm)>"
}
```

| 字段 | 类型 | 编码 | 解码后格式 | 说明 |
|------|------|------|-----------|------|
| `rgb_image` | `str` | base64 JPEG/PNG | `ndarray` uint8 `(H, W, 3)` BGR | 彩色图, 用于可视化显示 |
| `depth_image` | `str` | base64 16-bit PNG | `ndarray` float32 `(H, W)` 米 | 深度图, 0/NaN=无效, 用于 GGCNN 推理 |

**响应 (失败):**
```json
{
    "success": false,
    "error": "错误描述字符串"
}
```

#### 9.2.2 SimCamera 解码后的输出 (与 RealSenseCamera 兼容)

```python
color_bgr, depth_float32 = camera.get_images()
```

| 输出 | 类型 | 维度 | 值域 | 说明 |
|------|------|------|------|------|
| `color_bgr` | `ndarray` uint8 | `(480, 640, 3)` | 0~255 BGR | 与 RealSenseCamera 接口一致 |
| `depth_float32` | `ndarray` float32 | `(480, 640)` | 0~∞ 米, NaN 无效 | 与 RealSenseCamera 接口一致 |

### 9.3 输出 (本系统 → 仿真平台)

#### 9.3.1 抓取任务序列 (`/task`)

**请求:**
```
POST http://192.168.1.121:8080/task
Content-Type: application/json
```

**请求体 JSON 结构:**
```json
{
    "sequence": [
        {
            "arm": "arm1",
            "type": "move",
            "params": {
                "x": 230.0,
                "y": -50.0,
                "z": 300.0,
                "roll": 180.0,
                "pitch": 0.0,
                "yaw": -30.0
            },
            "wait": 0.5
        },
        {
            "arm": "arm1",
            "type": "set_object",
            "params": {
                "object": "box"
            }
        },
        {
            "arm": "arm1",
            "type": "vacuum",
            "params": {
                "on": true
            },
            "wait": 0.8
        }
    ],
    "arm_id": 0
}
```

> ⚠️ 仿真平台服务器 (`new2(1).py`) 要求 **`sequence` 中每个动作都携带 `"arm"` 字段**，
> 取值为字符串 `"arm1"/"arm2"/"arm3"`；顶层 `arm_id` (整数 0/1/2) 仅作兼容保留、
> 服务器实际不读取。`SimulationClient.post_task()` 会自动把 `arm_id` 映射成
> `"armN"` 并注入到每个动作 (见 `ARM_ID_TO_KEY`)。

#### 9.3.2 动作类型说明

##### move — 机械臂移动到目标位姿

| 参数字段 | 类型 | 单位 | 说明 |
|----------|------|------|------|
| `x` | `float` | mm | 基坐标系 X (前向) |
| `y` | `float` | mm | 基坐标系 Y (左向) |
| `z` | `float` | mm | 基坐标系 Z (上向) |
| `roll` | `float` | 度 | 绕 X 轴旋转 (通常 180 = 末端朝下) |
| `pitch` | `float` | 度 | 绕 Y 轴旋转 (通常 0) |
| `yaw` | `float` | 度 | 绕 Z 轴旋转 (抓取角 -90~90) |
| `wait` | `float` | 秒 | 动作完成后额外等待时间 |

##### vacuum — 真空吸盘控制

| 参数字段 | 类型 | 说明 |
|----------|------|------|
| `on` | `bool` | `true`=开启真空吸取, `false`=关闭真空释放 |
| `wait` | `float` | 秒, 动作完成后等待 (吸取建议 ≥0.8s) |

##### set_object — 绑定被抓物体

| 参数字段 | 类型 | 说明 |
|----------|------|------|
| `object` | `str` | 服务器场景物体名 (`sheet`/`cylinder`/`box`/`flange`/`bearing`)，开启真空前必须绑定 |

> ⚠️ 服务器 (`new2(1).py`) 的真空吸盘在开启前会做 `check_grasp_distance` 距离校验，
> 依赖 `set_object` 先绑定 `current_object`，否则返回 "没有指定抓取对象" 而吸取失败。
> 本项目物体类型 (`part_a/part_b/part_c`) 通过配置 `config_sim_3arms.json` 顶层的
> `object_name_map` 映射到服务器场景物体名。

#### 9.3.3 完整 pick-and-place 序列 (11 步)

TaskBuilder 根据 GGCNN 抓取目标 `[X, Y, Z, 180, 0, Yaw]` 生成的完整序列:

| 步骤 | 类型 | 目标位姿 | wait | 说明 |
|------|------|----------|------|------|
| 1 | move | `(X, Y, above_z)` yaw=Yaw | 0.5s | 移到目标正上方 |
| 2 | move | `(X, Y, above_z)` yaw=Yaw | 0.5s | 上方静置消抖 |
| 3 | move | `(X, Y, max(Z, min_z))` yaw=Yaw | 1.0s | 直线下降抓取 |
| 4 | set_object | `object=<server_object>` | 0s | 绑定被抓物体 (真空前必须) |
| 5 | vacuum | `on=true` | 0.8s | 开启真空吸取 |
| 6 | move | `(X, Y, detect_z)` yaw=Yaw | 0.5s | 抬升至安全高度 |
| 7 | move | `(release_x, release_y, detect_z)` yaw=0 | 0.5s | 平移至释放点上方 |
| 8 | move | `(release_x, release_y, release_z)` yaw=0 | 1.0s | 下降至释放高度 |
| 9 | vacuum | `on=false` | 0.5s | 关闭真空释放 |
| 10 | move | `(release_x, release_y, detect_z)` yaw=0 | 0.5s | 抬升至安全高度 |
| 11 | move | `(detect_x, detect_y, detect_z)` yaw=0 | 0.5s | 回到观察位 |

> above_z=300mm, min_z=70mm(安全限位), suction/release wait 可配置。
> 当未配置 `server_object` (无物体映射) 时跳过第 4 步，序列回退为 10 步。

#### 9.3.4 仿真任务配置 (SimGraspConfig)

与物理脚本配置一致, 通过 `TaskBuilder` 的 `SimGraspConfig` 数据类管理:

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `detect_xyz` | `list[float]` | `[200, 0, 380]` | 观察位 (mm) |
| `release_xyz` | `list[float]` | `[225, -89, 83]` | 释放点 (mm) |
| `above_z` | `float` | `300` | 安全悬停高度 (mm) |
| `grasping_min_z` | `float` | `70` | 最低 Z 限位 (mm) |
| `move_wait` | `float` | `0.5` | move 后等待 (s) |
| `descend_wait` | `float` | `1.0` | 下降后等待 (s) |
| `suction_wait` | `float` | `0.8` | 吸取后等待 (s) |
| `release_wait` | `float` | `0.5` | 释放后等待 (s) |

### 9.4 仿真模式运行方式

```bash
cd ggcnn_grasping_demo/simulation

# 真实相机 + 仿真机械臂 (默认)
python run_simulation.py

# 仿真摄像头 + 仿真机械臂 (全仿真)
python run_simulation.py --sim-camera

# 无相机测试模式
python run_simulation.py --no-camera

# 指定服务器地址和模型
python run_simulation.py --server http://192.168.1.121:8080 --model ../models/epoch_50_cornell

# 指定仿真摄像头内参
python run_simulation.py --sim-camera --cam-fx 615.0 --cam-fy 615.0
```

### 9.5 SimulationClient 接口汇总

| 方法 | HTTP | 端点 | 输入 | 输出 | 说明 |
|------|------|------|------|------|------|
| `check_connection()` | GET | `/` | — | `bool` | 测试服务器连通性 |
| `post_task(sequence)` | POST | `/task` | `list[dict]` (动作序列) | `dict` (响应 JSON) | 发送抓取任务 |
| `get_camera()` | POST | `/get_camera` | `{}` | `dict` (含 rgb_image/depth_image) | 获取仿真摄像头图像 |

### 9.6 仿真模式数据流全景

```

└─────────────────────────────────────────────────────────────────┘
        ↑ 任务序列 JSON                    ↓ 图像 base64 JSON

└───────────────────────────────────────────────────────────────────┘
        ↑ post_task()                       ↓ get_camera()
┌──────────────────────┐          ┌──────────────────────────┐
│     TaskBuilder       │          │      SimCamera            │
│  GGCNN目标 → 10步序列 │          │  base64 → numpy ndarray   │
│  安全限位 | 等待时间  │          │  RGB BGR | Depth float32  │
└──────────────────────┘          └──────────────────────────┘
        ↑                                    ↓
```

### 9.7 仿真模式可视化

OpenCV 窗口标题: `RealSense-D435 SIMULATION`

| 显示元素 | 内容 |
|----------|------|
| 左半窗 | 彩色图 + 状态栏 `SIMULATION MODE \| LOCKED/SEARCHING/NO OBJECT \| grasped:N` |
| 右半窗 | GGCNN 热力图 (JET 色映射 + 绿色圆点标记抓取位置) |
| 第二行 | 服务器地址 (灰色小字) |
| 抓取状态 | 锁定=绿圈, 搜索中=橙圈 |

按键交互:
- `q` / `ESC` → 退出程序
- 仿真服务器离线时: 窗口显示 `[SERVER DOWN]` 并继续运行, 自动重试

### 9.8 仿真模式与真实模式坐标变换对比

| 变换参数 | 真实模式 | 仿真模式 |
|----------|----------|----------|
| 末端位姿来源 | `arm.get_position()` 实时读取 | 硬编码虚拟位姿 `[0.2, 0.0, 0.38, pi, 0, 0]` |
| 手眼标定 `EULER_EEF_TO_COLOR_OPT` | 相同 | 相同 |
| `cam_result_to_base()` | 每帧使用当前末端位姿 | 每帧使用固定虚拟位姿 |
| 坐标系精度 | 取决于手眼标定精度 | 取决于虚拟位姿与仿真机器人实际位姿的一致性 |

> 仿真模式假设机器人始终处于观察位 `[200, 0, 380]` 且末端垂直朝下 (roll=180°)。若仿真平台中机器人实际位姿与此不同, 需修改 `get_sim_eef_pose_m()` 中的硬编码值。
