# 三臂协同抓取系统 — 设计方案

> 基于 `run_rs_d435_grasp_lite6_new_best.py` 单臂抓取方案扩展
> 三台 xArm Lite 6 + RealSense D435 + GGCNN2 视觉引导协同作业

---

## 1. 系统架构

```
config_3arms.json  →  SystemConfig
                             │
                  MultiArmCoordinator (中心协调器)
                  区域锁 | 安全监控 | 状态同步 | 故障检测
                    ↑            ↑            ↑
              ArmController  ArmController  ArmController
                Thread-0       Thread-1       Thread-2
                   │              │              │
              RealSense      RealSense      RealSense   (独立相机)
              GGCNN2         GGCNN2         GGCNN2      (独立模型)
              XArmAPI        XArmAPI        XArmAPI     (独立连接)
                   │              │              │
                   └──────────────┼──────────────┘
                                  │
                       MultiArmVisualizer (Thread-3)
                            组合显示窗口
```

**核心原则**：每臂独立运行（独立线程、独立相机、独立模型、独立机器人连接），通过中心协调器实现状态同步和碰撞避免。

## 3. 碰撞避免策略

### 3.1 空间分区（默认线形并排布局）

```
                      ┌─────────────────────────────────────────┐
                      │              工作台 (Table)               │
                      │                                         │
   Arm-0 (左)         │  独占区A   协调区AB   独占区B   协调区BC   独占区C  │        Arm-2 (右)
   基座(200,-250)     │  X:100~500 X:100~500 X:100~500 X:100~500 X:100~500│        基座(200,250)
      │               │  Y:-450~-100 Y:-150~-50 Y:-100~100 Y:50~150 Y:100~450│           │
      │               │                                         │           │
      ▼               │  [Arm-0专] [AB共享]  [Arm-1专]  [BC共享]  [Arm-2专]  │           ▼
   ┌──────┐           │                                         │        ┌──────┐
   │Arm-0 │           │    ●     ○    ●    ○    ●               │        │Arm-2 │
   └──────┘           │  (物体)                                  │        └──────┘
                      │                                         │
                      │       ▲  Arm-1 (中) 基座(200,0)          │
                      │       └──────────────────┘              │
                      └─────────────────────────────────────────┘
```

- **独占区**：仅拥有者可进入和操作物体
- **协调区**：相邻两臂共享，任一臂可进入但需持锁（互斥）
- **安全高度**：350mm — 穿越非己区域时 EE 必须保持此高度以上
- **安全半径**：100mm — 任意两臂 EE 间距小于此值立即急停

### 3.2 搬运路径规范

```
所有跨区移动路径：
  抓取点 → [抬升至安全高度] → [高位平移] → 目标正上方 → [下降]
  
  ✗ 禁止：低位斜穿他臂区域
  ✓ 允许：高位过顶穿越（始终 > 安全高度）
```

### 3.3 多层安全防护

| 层级 | 机制 | 响应时间 |
|------|------|----------|
| L1 软件 | Coordinator 区域锁 + 预判 | 移动前检查 |
| L2 软件 | 安全距离持续监控 (10Hz) | ~100ms |
| L3 固件 | xArm 内置碰撞检测 (灵敏度 ≥ 3) | ~10ms |

## 4. 协调区故障处理（★核心设计）

协调区是碰撞风险最高的区域。一个臂在此操作时故障，可能卡住位置阻塞其他臂。

### 4.1 故障分级

```
L1 可恢复 ─── arm.error_code ≠ 0 ───▶ 中止当前抓取
  (碰撞警告、伺服超限)                   → 抬升至安全高度
                                        → 释放协调区
                                        → recover() 恢复
                                        → 回观察位继续

L2 通信断开 ── arm.connected == False ──▶ 标记 DISCONNECTED
  或 get_position 连续3次失败             → 强制回收该臂所有区域
                                          → 通知操作员
                                          → 其他臂继续正常工作

L3 物理卡死 ── EE 10秒未移动 ──────────▶ 广播该臂区域为 HAZARD
  且不在观察位                            → 其他臂自动绕行
                                          → 可视化红色闪烁
                                          → 等待操作员介入清除
```

### 4.2 区域锁生命周期

```
                    [FREE] 自由
                       │
                       │ request_zone(arm_id)
                       ▼
              [OWNED by arm_id] 已占用
                       │
       ┌───────────────┼───────────────┐
       ▼               ▼               ▼
   正常释放         L1 故障恢复      L2/L3 强制回收
   release_zone()  抬升→释放→恢复   force_release()
       │               │               │
       ▼               ▼               ▼
    [FREE]          [FREE]          [HAZARD]
                                   需人工清除
```

### 4.3 关键机制

**① 区域锁租约 (Lease)**

区域锁不是永久的。每个锁有 30 秒租约，持有者每 5 秒续约一次：

```python
@dataclass
class ZoneLease:
    arm_id: int
    zone_name: str
    granted_at: float        # 授权时刻
    lease_duration: float    # 30秒
    renewed_at: float        # 最近续约时刻
```

- 租约超时未续约 → Coordinator 自动回收 → 通知等待队列中的下一个臂
- 防止"臂故障后永久占用区域"的僵死状态

**② 故障时安全抬升优先**

```python
def _handle_fault_in_coord_zone(self):
    # 第一步：尝试抬升（简单抬升命令通常即使有错误码也能执行）
    current_z = self._arm.get_position()[1][2]
    safe_z = 380  # 观察位高度
    try:
        if current_z < safe_z:
            self._arm.set_position(z=safe_z, speed=150, wait=True)
    except:
        pass  # 抬升失败进入 L2/L3 处理

    # 第二步：释放所有协调区
    self._coord.release_all_zones(self._config.arm_id)

    # 第三步：标准恢复
    self._recover()
```

**③ 等待者超时降级**

等待协调区时不做无限阻塞，分级降级：

```
等待 5 秒 → 超时
  ├─ Step 1: 尝试微移目标到独占区（换角度抓，避开协调区）
  ├─ Step 2: 放弃目标，清空缓冲，重搜索
  └─ 绝不无限等待
```

**④ 死锁自动打破**

```
场景：Arm-A 等 Arm-B 释放区域，Arm-B 等 Arm-A 释放区域
检测：定期扫描等待关系图，发现环路
处理：强制 arm_id 较小的一方放弃 → 打破循环 → 另一方获得锁继续
```

**⑤ HAZARD 人工介入**

当 L2/L3 故障无法自动恢复：
- 区域标记为 `HAZARD`，红色显示
- 所有臂视该区域为永久禁用
- 操作员按 `r` 键确认安全后清除

### 4.4 故障传播隔离

| 故障臂状态 | 对其他臂的影响 | 区域处理 |
|-----------|--------------|---------|
| RECOVERING | 无影响 | 自动释放所有协调区 |
| DISCONNECTED | 无影响 | 强制回收区域 |
| STOPPED | 独占区禁用，其他正常 | 释放协调区 |
| HAZARD | 周边设为禁飞区 | 全部绕行 |

## 6. 线程模型

```
Main Thread ─── 启动 4 个子线程 ─── 等待 Ctrl+C ─── 清理退出

Thread-0 (Arm-Left):   init → main_loop (100ms/帧) → cleanup
Thread-1 (Arm-Center): init → main_loop (100ms/帧) → cleanup
Thread-2 (Arm-Right):  init → main_loop (100ms/帧) → cleanup
Thread-3 (Visualizer): render_loop (30ms/帧 渲染)
```

**线程安全策略**：
- Coordinator 内部全用 `threading.Lock` + `threading.Condition`
- 每臂独立的 Camera / GGCNN / XArmAPI 实例 — 无共享
- Visualizer 帧缓冲区独立锁，临界区仅拷贝 numpy 数组

## 10. 设计决策总结

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 通信架构 | 中心化 Coordinator | 避免 N×N 网状通信 |
| 区域策略 | 独占区 + 协调区 | 空间隔离确定性强，协调区解决边界物体 |
| 控制模式 | 开环两段式 | 无下降漂移，比闭环伺服更稳定 |
| 碰撞防护 | 软件区域锁 + 固件碰撞检测 | 多层冗余防护 |
| 故障隔离 | 单臂故障不影响其他 | 独立线程 + 独立硬件 |
| 配置管理 | JSON 文件 | 可读可改，无需重编译 |
| 区域锁 | 租约制 (30s) | 防僵死，自动回收 |
| 锁等待 | 超时 + 降级 | 不无限阻塞 |
| 死锁 | 定期扫描 + 强制打破 | 自动恢复 |

## 11. 关键风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 相机 USB 带宽不足（3×D435） | 降低分辨率至 640×480、启用 USB3.0 独立通道 |
| 机械臂网络延迟 | 所有臂连同一交换机、位置命令本地执行不依赖网络 |
| GGCNN CPU 推理瓶颈 | 每臂独立模型实例、可扩展到 GPU |
| 手眼标定不一致 | 每臂独立标定参数、JSON 独立配置 |
| 协调区频繁竞争 | 独占区覆盖主要工作区、协调区仅边界使用 |
